# 使用习惯：省 Token 又出好结果

提示词只能管模型怎么做，下面这些要靠你自己的使用习惯。改编自《真正烧 Token 的 10 个习惯》，按"你该怎么做"重新整理。

## 会话管理
1. **一个任务一个会话。** 长对话每一轮都要重读全部历史，越往后越贵、越容易跑偏。任务结束先让模型输出总结文档，新任务开新会话，把总结贴进去。
2. **图片用完就退出。** 截图和图片很占上下文。先让模型把关键信息提取成文字，再带着文字开新会话继续。
3. **需求变了就改原提示词。** 不要一层层追加"再改一下""这个也要"。编辑原消息重新发送，旧要求就不会继续干扰。

## 给材料
4. **先索引，再按需调入。** 素材多时先让模型做一份目录或摘要索引，之后只调入相关的几份。
5. **只给相关片段。** 报错时贴报错片段和相关模块，不贴完整日志和整个代码库。大型代码库可以用 graphify 这类工具（见 `third-party.md`）。

## 提要求
6. **改哪段说哪段。** 只改一小段时说"只改第 2 段，输出修改后的这一段"，不要让模型重写全文。全局准则第 8 节已经要求模型这样做，你明确说出来会更稳。
7. **要结果就说要结果。** "直接给结论和步骤，不要背景介绍"。

## 选工具
8. **任务分级用模型。** 摘要、改写、分类、格式转换用便宜的小模型；策略、复杂推理、重要决策用强模型。
9. **Skill 按需开。** 本项目的 Skill 平时只占名称和描述的开销，可以常开；上百个 Skill 的第三方大合集只挑需要的装。
10. **Agent 要设刹车。** 自动执行的任务设置最大轮次。全局准则第 10 节已经要求"同一方法失败 3 次就停下汇报"；你自己搭的流水线也要在代码里设上限。

## 什么时候用哪个流程
不用记 Skill 名。直接说你的情况，模型会匹配：
- "我说不清哪里不对" → 问诊
- "A 和 B 选哪个" → 决策实验室
- "帮我挑刺" → 压力测试
- "这是真的吗" → 事实核查
- "我想学 X" → 导师
- "太浅了" → 深度化改写
