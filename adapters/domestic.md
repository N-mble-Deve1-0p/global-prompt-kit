# 国内模型适配（DeepSeek、通义千问、Kimi、智谱 GLM、豆包、MiniMax、混元等）

国内主流模型都能很好地理解中文 Markdown 结构的提示词，所以不需要逐个定制，统一使用 `dist/domestic.md`。

## 放在哪里
| 场景 | 位置 |
|---|---|
| 官方 App 或网页（有"自定义指令""个性化""智能体"等功能时） | 放进去；字数受限用 `core/global-prompt-lite.md` |
| 官方 App 没有这类设置 | 新对话的第一条消息粘贴精简版，后面接你的问题 |
| 通过 Cherry Studio、WorkBuddy 等客户端使用 | 见 `cherry-studio.md`、`workbuddy.md` |
| API | system 消息放 `dist/domestic.md` |

## 推理模型的注意事项
部分推理模型对系统提示词的遵循不如对用户消息稳定。例如 DeepSeek 早期推理模型（R1）的官方使用建议就是不加系统提示词、把指令写进用户消息。新版本未必还有这个问题，但保险做法是：
- 全局准则照常放在系统提示词或自定义指令里；
- 对最在意的 1–2 条要求（比如"标注来源""不确定就说暂未核实"），在用户消息里再说一次。

## 通用附加片段（构建时自动追加）
```markdown
## 模型补充说明
- 场景工具箱里的流程：支持 Skills 的环境对应已安装的同名 Skill；不支持的环境，我会粘贴 templates/ 下的同名模板，按模板执行。
- 不能联网时，涉及时效信息的回答要说明"基于训练数据，可能已过时"。
- 使用中文网络来源时同样区分级别：官方网站、政府公告、上市公司公告、论文属于一手来源；自媒体文章、百科、问答社区属于二手来源，需要标注。
- 不要在回答末尾附加与问题无关的延伸推荐。
```

## 小模型的注意事项
参数较小的本地模型很难同时遵守十几条规则。建议只保留精简版的第 1、2、5、6 条，并把场景模板拆成单独对话使用。
