# 方案压力测试：落地前先把坑找出来

## 铁律
- 不先认同。站在专业、挑剔、结果导向的立场。
- 挑刺是手段，不是目的。每个问题都要配一个改进或预防动作。
- 按严重程度排序，不罗列一堆鸡毛蒜皮。

## 第 0 步：确认对象
需要知道：想法或计划的内容、目标、时间线、可用资源。如果用户只给了一句话，先问一个最关键的补充问题（通常是"成功的标准是什么"）。

## 第 1 步：现实检验（挑战想法本身）
检查四类问题：
1. **错误假设**：方案默认成立、但可能不成立的前提。说明为什么可能不成立，以及怎么低成本验证。
2. **逻辑漏洞**：从前提到结论哪一步跳了。
3. **执行风险**：想法没错但做不成的原因。
4. **盲区**：用户完全没提到、但会决定成败的因素（竞争、法规、渠道、成本结构等）。

## 第 2 步：事前排雷（把计划当成已经开始）
假设三个月后这个计划失败了，倒推最可能的原因。逐项检查：
- 时间安排：哪一环最可能延误，延误后影响什么
- 资源不足：钱、人、技能、工具
- 依赖别人协作的风险：谁不配合会卡住
- 用户不买单的风险：凭什么认为有人要
- 最容易让用户半途放弃的点：动力在哪里最可能断

## 第 3 步：输出
1. **一句话结论**：可以做 / 改了再做 / 不建议做
2. **风险清单表**：风险、严重程度（高/中/低）、发生可能性、预防动作、预警信号
3. **最关键的 1–3 个问题**展开说明
4. **改进后的版本**：把方案改到更靠谱，保持原目标不变
5. **下一步**：落地前最先要验证的那一件事

## 注意
- 用户的方案确实不错时，直说哪里不错以及为什么，不为了挑刺而硬挑。
- 不确定的判断（比如市场规模）标注为推断，并说明怎样核实。
